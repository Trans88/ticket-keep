# 票证记 UI / UX v2 —「好好收着」

设计日期：2026-09-19。依据当前 Kotlin 源码与工作区未提交版本梳理；没有运行原 Android App，也没有改动生产业务代码。README 的功能清单已落后于源码，实施时以实际代码为准。

## 1. 交付与阅读顺序

1. `index.html`：可离线打开的六屏交互原型，无外部字体、图片或脚本依赖。
2. `index.html?view=board`：六屏视觉总览。也可打开原型后点击「打开六屏设计总览」。
3. 本文件：产品结构、交互规范、异常状态、视觉参数。
4. `tokens.json`：浅色 / 深色语义色、字体、尺寸与动效参数。
5. `GORK_IMPLEMENTATION.md`：面向实现助手的任务顺序、代码映射与验收要求。

原型中的商家、票证、账号、口令示意和日期全部是合成示例；基准日期固定为 2026-09-19。保存仅修改页面内存，刷新重置。拍照、OCR、支付、加密、导出与网络请求均未执行。它是设计参考，不是可以嵌进 Android 的产品界面。

原型展示正常态、首页空态、无搜索结果、手动录入、浅 / 深色、渠道切换和关键对话框。日期范围筛选、真实账号表单、设备权限、OCR 失败 / 加载、商店失败等状态以本规范为准，不声称原型已完整模拟。设计目录可直接进入 Pro / 备份特权页面供审阅；正式 App 仍必须执行权限检查。

## 2. 设计判断

产品是本地优先的收据与保修管理工具，核心顺序是「收好 → 找到 → 用上」。不把它设计成报销平台、消费记账软件或带社交账户体系的综合工具。

现有界面的问题来自代码结构：

- `ListScreen` 将搜索、多个筛选、计数、通知 / Pro 引导排列在同一层，首屏可见记录较少。
- `EditScreen` 长表单中，购买信息、保修模式、OCR 原文的层级不够明确。
- `DetailScreen` 先放大图，再分散显示商家、保修和字段；用户找保修信息需要往下看。
- `SettingsScreen` 用大卡片解释系统权限和后台机制，并存在面向开发者的 WorkManager 文案。
- `PaywallScreen` 有商品 ID / 内测配置等技术报错，面向普通用户不合适。
- 云备份已有账号 / 上传 / 恢复分段和安全确认，应优化其呈现，不推翻现有行为。

视觉方向：暖白色纸张、森林绿、少量嫩绿色点缀、柔和橙色临期提示。采用稳定的排版、间距和图标建立品质感。拒绝过大的数据仪表盘、金色 VIP、每一行都加厚边框、无意义渐变与满屏阴影。

现有应用已经用薄荷绿，本次保持绿色品牌连续性，但降低高饱和青色比例、提升标题和内容层次。首页文案「重要的凭证，好好收着。」；品牌句「让凭证有处可寻」。英文小标题仅是原型装饰，正式中文版可以替换为「保修小记」，不能承担唯一的功能说明。

## 3. 信息结构

- 票证：搜索、快捷筛选、记录列表、临期入口。
- 添加：底部中间的动作按钮，不是独立 Tab；展开拍照 / 相册 / 手动填写底部面板。
- 我的：本地票证册与额度、加密云备份、导入导出、保修提醒、隐私与关于。
- 票证详情：购买信息、保修信息、原始图片、OCR 原文、编辑、导出与删除。
- 新建 / 编辑：预览及核对 → 基本信息 → 保修 → 备注 → 保存。
- 云备份：权益校验 → 登录 / 注册 → 备份状态及列表 → 上传 / 恢复。
- Pro：权益说明、真实商品价格 / 周期、购买结果、恢复购买。

仅「票证 / 我的」显示底栏，详情、编辑、备份、Pro 占满内容区。Android 系统返回遵循导航栈，不能只按页面类型硬编码跳回。

### 底部导航 v2.2：悬浮玻璃材质

替换贴边实色底栏，采用圆角悬浮胶囊。保留票证 / 添加动作 / 我的三项语义，不增加目的地。设计受透明玻璃材质启发，不承诺复刻苹果系统的专有渲染效果。

- 参考尺寸：左右外距 14 dp，容器约 72 dp 高，圆角 36 dp，内部 7 dp。底部在系统手势安全区上方留出 8–12 dp，不能机械照搬网页的固定 21 px。三键导航使用实际 inset。
- 正文从标题、概览、搜索至列表仍在同一个滚动容器中；正文延伸到玻璃后方，导航不随正文滚动。列表末尾添加“导航实测高度 + 底部 inset + 浮起间距 + 额外 16 dp”的 contentPadding，使最后一条能完整滚出遮挡区；不要同时重复计算 Scaffold 和列表 inset。
- 浅色参考：暖白约 64% 不透明度、22 px 背景模糊、155% 饱和度、细亮边与柔和外阴影。深色改为约 73% 深绿材质，降低边缘高光，不直接套用白玻璃。
- 材质只作用于导航背后内容，图标与文字保持清晰，禁止给整个导航组件连同按钮文字一起模糊。中心主按钮保持高对比森林绿（深色为浅青柠），不做难以识别的全透明按钮。
- 选中项使用柔和胶囊底，并保留文字、图标及无障碍选中状态，点击区至少 48 dp。模糊不能作为保障对比度的唯一手段，须用实际滚动背景检查文字可读性。
- 弹出新增面板时，遮罩和面板覆盖导航，不能误触下层按钮。搜索键盘弹起时正式 App 暂时隐藏导航，关闭键盘后恢复；编辑等非主页面本身不显示导航。
- 无背景模糊支持、性能不足、减少透明度或高对比模式时回退为高不透明度材质（浅 #F3F7EF，深 #26392D），保留外距和圆角。网页已有能力/偏好回退，Android 必须独立实现并真机验收。不要每帧截图整页制造模糊，不做持续闪光或折射动画。
- 大字号时允许容器增高、按钮文案换行，并按实测高度调整底部空间；不能裁字或缩小点击区来凑固定高度。品牌色、业务、会员与备份规则不因材质变化而改变。

## 4. 六个核心页面

### 4.1 票证首页

从上到下：品牌标题和通知入口 → 临期摘要 → 搜索 → 横向快捷筛选 → 列表 → 固定底栏。

摘要高度目标 156–176 dp，最多两行标题；有临期时展示数量和「查看 30 天内到期」。数量统计全量票证，与搜索无关。进入搜索 / 筛选结果时可收起摘要，给记录更多空间；首用空态不展示无意义摘要。无临期显示「最近没有临期保修」，没有填写保修日期不等于安全在保。

快捷筛选为全部 / 即将到期 / 未过期 / 未设保修。更多筛选中保留已有「已过期」以及购买日 / 到期日范围。全部仍按 `createdAtMillis DESC`；不新增不可用排序入口。

「即将到期」是本设计新增的 UI 快捷状态，可映射到现有筛选：`NOT_EXPIRED + WARRANTY_END + [today, today+30]`。点击时一次性替换旧日期条件，不能留下旧购买日筛选。状态判定使用 LocalDate，包含今天和第 30 天。「未过期」包含临期；「未设保修」单独计数。摘要统计需要全量数据，不能直接拿 `ListUiState.tickets`（它已过滤）。

高级筛选面板包含日期字段单选、开始日、结束日、「清除」「应用」。面板内先编辑草稿，取消不应用；开始晚于结束时原位提示且禁止应用。应用后搜索框下显示可清除的筛选摘要。返回详情或切 Tab 后保留搜索、筛选和列表滚动位置。

单条票证：左侧 44×54 dp 图片缩略图 / 通用票据图标；中间商家 14–16 sp、备注与购买日；右侧金额与保修状态。不得把 `note` 虚构成独立商品名字段。缺失金额显示「—」，不显示 ¥0.00；空商家显示「未命名商家」；缺失购买日显示「未设购买日」。列表缩略图可裁切，详情原图不能只裁切。

宽度紧张、字号放大或金额很长时：备注最多两行；金额和状态下移，允许卡片自动增高，不能遮挡、挤掉商家。数据量大时保持 LazyColumn，不改成整页 eager Column。

通知提示不与 Pro 横幅竞争。首次成功保存带保修日期的票证后，用一次轻量面板说明提醒价值，再由用户触发系统授权；拒绝后不循环弹出。「我的 → 保修提醒」长期可达。现有持久化关闭状态需要迁移或尊重。

### 4.2 票证详情

顶部返回 / 标题 / 更多；中央票证摘要先显示商家、备注、金额、到期状态。下方购买字段、原图预览、默认收起的识别原文。编辑操作在更多菜单始终可达。

临期卡显示真实剩余天数；0 天显示「今天到期」，过期使用低饱和中性色。通知未授权时写「开启通知后接收到期提醒」，不能写成已经安排成功。无保修日期显示「未设置保修」，提供编辑入口。

主按钮：`showProExport=true` 时展示「准备送修材料」，走当前 Pro 门禁；否则展示「编辑票证」。PDF 和送修材料必须沿用现有导出器。没有票据图片时不显示伪造图片，改为「未添加原始凭证」轻提示；保留文本信息可用。

删除使用确认弹窗：说明删除票证并取消本地提醒，主视觉保留票证，危险按钮文字红色。当前不支持撤销，不展示假撤销 Snackbar。删除完成返回列表，保留原筛选上下文。记录不存在与加载中使用独立 UI 状态，避免刚打开就闪「已删除」。

### 4.3 识别与录入

新建进入相机 / 系统 Photo Picker / 空白表单。取消选择返回原位置，不落空记录。相机只在用户选择拍照时请求权限。

有图时顶部为 96–120 dp 收据预览；OCR 运行中展示轻量进度与「正在读取票据文字」，禁用保存。完成时「已识别部分信息，请核对后保存」。没有置信度字段，不显示 98% 等数值。无图时仅用手写图标和「手动记录」，不要展示样例票据。

按三个组展开：基本信息（商家、金额、购买日）；保修信息（按月数 / 手选日期 / 不设置）；备注。两列只在宽度与字号允许时使用，窄屏回到单列。购买日未识别保持 null，不自动填今天。金额以元展示、以分存储；输入非法不静默变成 null，应标出问题并保留文字。商家、金额和日期当前可空，设计不擅自增加必填限制。

「不设置保修」是新增交互，保存时明确清空 `warrantyMonths` 与 `warrantyEndEpochDay`；不能只禁用控件但保留旧值。按月数时日期只读，并通过 LocalDate.plusMonths 计算月末；购买日为空时提示补日期或手选到期日，不能制造到期日。手选模式不依赖购买日。保修日期早于购买日期应提示核对，不假装 OCR 可信。

OCR 原文默认收起。重新识别沿用现有保留手动字段策略，并说明覆盖范围。识别失败给「手动填写」和「重试」，原图和手填内容不能丢失。相机 / 图片处理出错与 OCR 没有识别到内容用不同文案。

保存底栏高度按内容自适应，52 dp 主按钮；正确处理 `ime + navigationBars`。OCR 中或保存中禁用重复提交；保存失败留在原页并保留输入。金额、日期相关错误显示在字段旁；不是所有错误都仅用顶部 Snackbar。

保存成功后进入详情并提示「已保存到本机」。系统返回 / 顶部返回 / 手势返回均在 dirty 时询问「继续编辑 / 放弃修改」，未修改直接返回。草稿及表单需在旋转、进程恢复允许范围内保留，使用 SavedStateHandle / rememberSaveable；不把备份口令长久保存。

### 4.4 我的

使用「本地票证册」，不假设用户已登录、不杜撰用户名称。容量展示真实条数和 freeLimit；Pro 用户显示「Pro · 不限条数」，不再显示 10 张进度条。原型默认免费状态。

数据与备份：加密云备份（标 Pro）、导入与导出（仅支持渠道）；使用偏好：保修提醒；关于：隐私政策、现有备案信息与版本。发布版本保留现有必需信息，版本号从 BuildConfig 取值。

提醒面板优先显示通知状态 / 测试通知；后台电池、自启动说明收入「收不到提醒？」折叠区。用「允许后台运行，可能有助于及时提醒」代替 WorkManager、精确闹钟等实现术语。

### 4.5 加密云备份

现有 `CloudBackupRepository` 上传、准备恢复和确认导入均检查 Pro，外层导航和 Screen 也有检查，必须保留。原型从设计目录进入时明确为 Pro 场景。普通免费用户从「我的」进入：Play 转 Pro 说明；China 若没有有效权益则显示暂未开放，不能在“备份 / 付费墙”之间循环跳转。有效已有权益不因渠道名称强行判为失效。

未登录：简洁价值说明，主按钮登录；在账号面板选择登录 / 注册，邮箱、账号密码（当前至少 8 位）、提交中及错误提示。不要开发无后端支持的“忘记密码”。账号密码与备份口令严格区分。登录完成才拉取列表。

已登录：账号摘要、最近备份日期、实际字节大小、服务端确有字段时才展示记录条数、上传按钮、备份历史、退出登录。只表示「最近上传成功」，不能表示“所有最新内容都已同步”。

上传：点击备份 → 设置口令与确认口令（沿用当前至少 6 位校验）→ 本地加密 → 上传中 → 成功刷新列表。说明忘记口令无法解密，失败保留本地数据、可重试。没有真实进度时用阶段文字 / 不定进度，不编造百分比。

恢复：选副本 → 提示将新增且保留本地数据 → 输入口令并确认 → 下载、解密 → 展示新增数、跳过数、图片情况 → 最终确认导入 → 完成。无自动去重，明确重复恢复可能重复。口令错误留在口令步骤，不导入；导入异常不能谎报全部成功。保留当前确认边界。

删除云端备份与删除本地票证分开，标题明确删除对象，提示云端副本不可恢复、本地不受影响。退出账号保留本地票证。Base URL 继续仅 Debug 高级折叠中出现，普通用户不用看到服务器地址。

### 4.6 Pro

**v2.1 修订：以普通版 / Pro 对比为主，不再使用三个独立卖点卡片。** 信息顺序：当前身份与用量 → 紧凑价值区 → 权益对比 → 基础免费功能 → 使用边界。购买区固定在滚动正文之外。原型顶部“会员演示状态”仅供设计验收，不能成为正式 App 的切换权益入口。

| 功能 | 普通版 | Pro（Play） |
|---|---|---|
| 票证数量 | 最多 10 张 | 不限数量 |
| PDF / 送修材料 | 不支持 | 支持 |
| CSV 导入与导出 | 不支持 | 支持 |
| 加密云备份 / 恢复 | 不支持 | 支持 |

拍照识别、手动录入、搜索筛选、保修提醒、本地保存和已有票证的查看编辑单独列为双方共有，不把基础功能包装为付费权益。数量取 freeLimit 与实际记录数，不硬编码原型的 10 与 4。不限制票证数量不等于承诺无限云端存储容量。

对比表按行构建，列宽比例约 40 / 28 / 32。Pro 列用柔和绿色背景，首行“不限数量”适度强调。行高随内容和字体增长，不能用三个各自独立的 Column + 固定行高拼表；否则大字号换行后会错位。窄屏 / 大字号可改为逐项上下布局，保留“普通版 / Pro”标签，不截字、不横向溢出。

普通用户：展示“当前：普通版 · 免费”和用量，普通列标“当前方案”。已开通：显示“当前：Pro 会员”、标题“你的 Pro 权益”，Pro 列标“当前方案”；购买区改为“你已开通 Pro / 继续使用票证记”，不再推销或允许重复开通。真实订阅周期、到期或续订状态须有 Billing 数据才显示。

国内渠道的 PDF / 送修材料与 CSV 行在 Pro 列标“未开放”，注明渠道限制，不暗示付费即可解锁尚未开放的功能；国内普通用户的底部为“国内渠道暂未开放购买 / 继续使用普通版”。已有 Pro 权益不可因渠道名被覆盖。原型 Play 当前演示价格获取失败，底部提供“重新获取价格”和“恢复购买”；这不是实际商店状态。

网页中每行保持同级 DOM，表格与购买区不可嵌进权益行内。正文滚动、底部操作独立，避免此前未闭合标签造成的横向挤压。

价值为不限票证数量、CSV/PDF/送修材料、加密手动备份。明确保修提醒与已有票证查阅、编辑不应被视觉改版误锁。当前 freeLimit=10；实际功能资格仍以业务代码为准。

只做已有 Play Billing 的视觉适配。价格和计费周期必须来自真实商品与已选择 offer，恢复购买可见。当前原型刻意没有写价格、终身套餐和折扣，不能据此新增收费策略。订阅展示续费与取消说明；如产品不是订阅则不要显示订阅条款。

价格加载中：骨架 / “正在获取价格”，按钮不可购买；失败：“暂时无法获取价格，请稍后重试”；不可展示商品 ID、内测配置提示。购买处理中防重复，用户取消不显示“系统错误”；pending 明确“付款确认中”，不提前授予权益；成功展示已开通并返回原任务；恢复无订单说明“暂未找到有效购买”。失败后可重试，不吞掉业务错误。

China：`showProPurchase=false`，隐藏主动销售入口；达到上限时说明当前限制，允许继续看与编辑已有内容。不得加假的微信 / 支付宝按钮，也不得将开发者调试 Pro 开关放入 Release。该渠道今后支付接入是独立任务。

### 排版、空间和形状

中文使用 Android 系统 Sans 字体，数字采用等宽数字特性 tnum；不强制下载自定义字体。中文不压缩字距。标题 28/36 sp，页面标题 22/30，卡片标题 16/24，正文 14/22，辅助文字 12/18，标签 11/16，金额 36/44（常规页面 16/22）。金额不必极粗，500–600 即可。正文不低于 12 sp；原型的小字号仅作密度示意，Android 以此规范为准。

页面左右 20 dp（360 dp 屏可用 16）；垂直步进 4/8/12/16/20/24/32。主卡片圆角 22，记录卡 18，字段 12，主按钮 15，底部面板 26，状态标签 7。边框 1 dp，非层叠内容无需阴影。仅浮层 8 dp elevation。

触控目标至少 48×48 dp；主按钮 52 dp，列表最小高度 96 dp。状态徽标不是按钮，可小于 48 dp。图标 22–24 dp、统一约 1.7 dp 线宽；优先复用同风格 Material outlined 图标。票据抽象线条用 Compose / VectorDrawable 绘制；不需要位图素材和第三方商标。

小屏（320/360 dp）和 200% 字号必须重新排布；不能固定整张卡片高度。720 dp 以上可使用列表 / 详情双栏，但这是后续适配，不要求首轮重写导航。原型的手机边框、状态栏时间、英文注释、左右设计侧栏不进入实际 App。

## 6. 状态与文案验收

| 场景 | 应显示 / 行为 |
|---|---|
| 首次空列表 | 给重要的票证，一个家；存入第一张票证 |
| 搜索为空 | 没有找到这张票证；清除搜索与筛选 |
| OCR 空结果 | 没有识别出可用信息，可以对照图片手动填写 |
| OCR 失败 | 识别暂时失败；重新识别 / 手动填写 |
| 金额非法 | 金额请填写非负数字，最多两位小数 |
| 保存失败 | 没有保存成功，请重试；保留输入和图片 |
| 免费到 10 条 | 提前拦截新增；编辑旧票证仍允许 |
| 国内渠道额度满 | 当前版本最多保存 10 张，暂未开放会员购买 |
| 记录加载 | 占位，不显示“已删除” |
| 记录不存在 | 票证不存在或已删除；返回票证册 |
| 通知拒绝 | 票证已保存，提醒暂未开启；稍后可在“我的”开启 |
| 上传失败 | 备份未上传成功，本机票证不受影响 |
| 备份口令错误 | 无法解密，请核对这份备份的口令 |
| 无云端副本 | 还没有备份；创建第一份备份 |
| 恢复确认 | 将新增 N 张票证，保留本机记录；重复恢复可能重复 |
| 价格失败 | 暂时无法获取价格；重试 |
| 购买处理中 | 正在确认购买，请稍候；避免重复提交 |

TalkBack 顺序与视觉顺序一致；票证行读商家、金额、购买日及状态，装饰图标隐藏。输入错误需可被读出，密码显示按钮有明确状态名称，底部面板有标题和合适焦点恢复。图片 contentDescription 区分缩略图、查看原图。不得通过颜色单独表达临期、成功或错误。

## 7. 明确不新增的产品能力

本次没有设计数据库中的商品标题、分类、标签、收藏、文件夹、附件多图、家庭共享、自动云同步、AI 对话、消费分析、支付充值或新的会员套餐。想做这些需单独排期。首页概览仅对已有字段做统计；提醒天数仍为现有默认值，不添加实际上无法保存的开关。

改版需要新增少量展示状态：临期快捷筛选、筛选草稿、表单 dirty、无保修模式、保存异常处理、列表初始加载与不存在的区分、账号面板展示。新增 UI 状态不得改动存储结构、加密协议、恢复语义与支付计费策略。
