# grok 实现任务：本地高级功能买断 + 云备份年费

## 任务与范围

项目：`E:/project/ticket-keep-mvp/ticket-keep`。

用户已选定的商业方向：本地高级功能一次性解锁；有持续成本的云备份按年收费。请依据此方向重构权益与购买体验，而不是只替换 Pro 页面文案。此文件优先于旧 `DESIGN_SPEC.md`、`GORK_IMPLEMENTATION.md` 中“单一 Pro 订阅包含所有功能”的商业设定；它们的布局、可访问性和数据安全规范仍适用。

本任务书不代表已经完成实现，也不代表已经创建商店商品。先检查 AGENTS.md、git status/diff 和当前实际代码，保护其他助手与用户的未提交修改。不要覆盖整份文件、重置工作区、提交推送、创建正式商店商品或部署生产服务器。需要服务端更改时可在本地准备代码与迁移，但上线、凭据、真实支付测试和正式商品配置需用户另行操作或确认。

## 1. 产品划分

| 能力 | 普通版 | 本地高级版（一次性购买） | 云备份服务（年费） |
|---|---|---|---|
| 拍照 OCR、手动录入、搜索筛选、保修提醒 | 有 | 有 | 不改变本地资格 |
| 票证数量 | 现有免费上限，当前为 10 | 不限条数 | 不自动解除本地条数限制 |
| PDF / 送修材料导出 | 按现有免费限制 | 解锁 | 不自动解锁 |
| CSV 导入与导出 | 按现有免费限制 | 解锁 | 不自动解锁 |
| 加密云端备份与恢复 | 不含 | 不含 | 有效服务期内提供，须登录备份账号 |

上表把两种权益独立建模，不引入“先买本地版才能买云服务”的硬门槛；这是为避免擅自捆绑采取的设计建议，需用户确认再开放销售。如果用户希望云服务只供本地高级版用户加购，只能新增购买资格规则，不能重新合并权益字段。

云服务不暗含自动同步、多设备实时合并、无限空间、无限历史副本或家庭共享。当前仅有手动加密备份，继续保持真实能力边界。

一次性解锁指已购买的本地高级功能没有周期续费，不承诺所有未来独立产品、永远免费云服务或永不停止维护。不同平台和商店账号的跨平台互认不得擅自承诺。

## 2. 权益模型与门禁

当前 `ProPreferences.kt` 只有 `is_pro` / Debug override；`BillingManager.kt` 只查询订阅并统一写回 Pro；`BillingConfig.kt` 的旧商品为 `ticketkeep_pro_yearly`。这不足以表达新模型。

建立统一的权益仓库及可测试状态模型，例如：

- 本地买断：未知 / 未拥有 / 已拥有 / 已撤销，含来源与最近可信验证时间。
- 云订阅：未知 / 有效 / 已取消但尚未到期 / 宽限期 / 暂停或保留 / 已到期 / 已撤销，含可信到期时间与验证状态。
- 旧订阅：单独的兼容来源，不等同于买断。
- 派生能力：canAddUnlimited、canExportPdf、canImportExportCsv、canUploadCloud、canRestoreCloud 等。

具体命名可顺应代码，但不能继续用一个 `isPro` 决定所有权限。未知或查询失败不等于未购买；分别更新两类查询结果，不能让云订阅的空结果清掉本地买断。

应用内退出备份账号不应撤销仍有效的商店本地买断。本地买断验证成功后的日常本地使用不能强制联网或强制注册云账号；离线策略要明确，可信退款/撤销到达后正确更新。本地缓存不是云服务的授权凭据。

免费用户仅订阅云服务时，恢复不能通过截断、丢弃或静默跳过记录来满足本地上限。优先保留原有追加恢复语义；恢复造成超额后保留所有数据，限制后续新增而非查看编辑。CSV、云恢复和手动新增的限额边界应分别测试并在发布前说明。

## 3. 购买与服务端验证

- Google Play 本地买断采用非消耗型一次性商品，云服务采用独立订阅商品；不能通过“消耗购买”实现买断，也不能只修改旧订阅的名称冒充一次性商品。
- 分别查询商品与已拥有购买，价格和适用计费周期来自真实商品、选中的 offer 与计费阶段。不得取一个不相关的首项价格作为全部商品价格。
- PENDING 不授予权益；验证、发放和确认购买应可重试、幂等，处理重复回调、重装恢复、退款、撤销和网络失败。
- 云购买前明确关联备份账号；服务端绑定购买凭证与账号并防重复认领。不得因为客户端上传 `isPro=true` 就授予云空间。
- 检查现有云后端是否已有订单验证；若没有，补齐服务端向 Google 验证购买、更新订阅状态、处理通知及对账的方案和本地实现。API 凭据留在服务端，不写进 APK、仓库、日志或任务说明。
- 云列表、上传、下载/恢复、删除等接口分别执行身份、资源归属及相应权限检查。删除本人副本等数据管理操作不要简单等同于新增备份权限。
- RTDN 是状态变化通知，收到后重新查询可信购买状态；取消自动续费不等于立即到期，宽限期与暂停等遵循实际订阅状态，不只依靠手机时间。
- 当前 China 关闭购买和导出。第一阶段保持渠道配置；新收费策略不自动授权接入微信、支付宝或打开国内支付。国内商品、支付渠道和导出开放策略需另行确认。

## 4. 云到期与用户数据

云服务到期只影响云服务，不撤销有效的本地买断，不删除本地票证、图片、已下载备份或已导出的文件。本地已有内容仍可查看、编辑；本地高级功能由本地买断或兼容权益决定。

新增上传在可信状态判定不可用时停止。已有云副本的保留期、到期后下载/恢复窗口及免费额度需要用户确定，不能擅自设为零天，也不能承诺无限期免费保管/下载。先分离上传权限与数据取回权限，提供策略接口及测试；待确认前不要部署自动删除任务或开放新的正式订阅销售。有效保留窗口内允许用户取回其资料，不要求重新付费才取回；窗口长度、费用承担和通知方案需确认。

备份到期不是改变加密协议的理由。保持口令加密、服务端不掌握解密口令、恢复先预览后确认、保留本地并追加且不去重的原有语义。不要假装提供口令找回。

## 5. 老用户迁移

先确认旧 `ticketkeep_pro_yearly` 是否有真实订单/订阅者。不能从代码或本地布尔值猜测没有付费用户。

- 先保留旧商品的验证、恢复及独立兼容路径，依据可信旧订阅状态兑现既有权益，不因新版发布立即缩水。
- 老年度 Pro 不能自动转换成永久本地买断，也不能擅自取消用户订阅、修改扣费或开启第二笔订阅。
- 是否赠送老用户买断、旧订阅何时停止新售、续订后如何提供服务，由用户确认。未确认前保留旧行为并隔离新销售入口。
- 本地旧 `is_pro=true` 只作为待验证缓存/迁移提示，不是永久授权证明；Debug 模拟状态不能迁移成正式购买。
- 无法验证时保持非破坏性状态，不清数据、不强迫用户重复购买，提供重试与恢复购买。

## 6. UI / UX

命名建议：票证记高级版（一次购买）与加密云备份（按年服务），不再用一个“开通 Pro”按钮混在一起。

购买页用两个上下排列的独立方案区，不做手机上的四列拥挤大表：

1. 本地高级版：不限条数、PDF/送修材料、CSV；清楚写“一次购买，无周期续费”“不含云备份”。已有买断显示“已解锁”。
2. 云备份：加密手动备份、换机恢复、实际空间/副本限制、计费周期；清楚写“单独付费，不自动解锁本地高级功能”。未配置额度或价格不得展示虚构数字。

每个方案各自加载、失败重试、购买中与已拥有状态；全局可保留一个“恢复购买”，恢复结果要说明恢复了哪项。普通、仅买断、仅云订阅、两者都有、云到期这五种身份都要设计并测试。“我的”页分别显示本地版与云状态。

如商店商品是自动续订，购买前清楚显示续费与取消说明；若按年预付，则显示到期续购，不能把“按年收费”擅自等同为某一种续订形式。未确认计费形式时先完成状态与布局。

## 7. 分阶段交付与待确认项

第一阶段可以立即做：现状审计、拆分权益、可配置商品结构、Debug 状态矩阵、门禁与 UI、迁移保护和自动测试。不得修改生产数据与正式商店状态。阶段完成给出 diff 概述、测试结果和未完成项。

第二阶段在用户确认以下事项后才接通新商品销售与上线：

- 本地买断价格、云服务年价、币种/地区及实际商品 ID。
- 云服务自动续订还是按年预付。
- 云空间、单文件限制、历史副本数量与流量/频率限制。
- 到期后的保留期、资料取回窗口、提前通知和最终删除规则。
- 云服务能否独立购买（本任务书暂按独立建模）。
- 旧订阅真实订单情况与兼容/迁移政策。
- 国内渠道的购买和导出开放策略。

配置缺失时安全禁用相应销售入口并解释原因，不把缺失配置解释成用户无权益。让开发者手动完成商店与服务器凭据配置；不要在聊天里索要私钥或服务账号密钥。

## 8. 验收底线

- 无购买、仅买断、仅云订阅、两者都有、云到期且有买断、旧订阅有效、旧订阅待验证的能力矩阵测试。
- 一次性商品恢复与订阅恢复独立；退款/撤销仅影响对应权益。
- 云取消但尚未到期仍可按状态使用；过期不影响本地买断。
- 云账号 A 的订单不得在 B 认领；跨账号资源访问被拒绝；客户端改布尔值不能绕过服务端。
- 重复回调不会重复发放；PENDING 不解锁；网络失败不误清买断；重装可恢复有效购买。
- 所有现有票证、图片、导出文件和已下载备份不因迁移或到期而删除。
- China/Play、深浅色、窄屏大字号、价格失败和已有权益 UI 验证。
- 执行适用单元测试与两个渠道构建；未做真实商店、后端或真机测试必须明确标注，不得声称全部完成。
